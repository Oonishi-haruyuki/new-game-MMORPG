# マルチプレイ動作診断・状態確認HUD強化 & オフライン自動フォールバック計画

Aetheria Onlineにおけるリアルタイムマルチプレイ通信（WebSocket）の完全同期を確立し、接続状態を常時可視化する状態バッジ・詳細診断HUD、およびオフライン時にも探索や戦闘を中断させない堅牢な自動フォールバック機構を導入します。

> [!IMPORTANT]
> **確認済み仕様（ユーザー回答の反映）**:
> 1. **検証・機能方針**: 「現在の動作診断と状態確認HUDの強化」を採用。リアルタイムPing計測、参加プレイヤー一覧、ワンクリック通信テスト機能を備えた診断パネルを実装します。
> 2. **切断時・不安定時の挙動**: 「オフライン自動フォールバックと接続状態バッジ表示」を採用。サーバー切断時でもゲームを停止させず単独プレイへ即時移行し、バックグラウンドでの静かな自動再接続とステータスバッジ（接続中・オフライン・再試行中）の明快なフィードバックを提供します。

---

## 1. 概要 & コアコンセプト

- **機能の目的**:
  - 現在のマルチプレイ通信において、クライアント接続時の `join` パケット送信とサーバー側登録ハンドシェイクの不整合を解消し、同一ワールド内の冒険者同士が互いの姿・移動・スキル詠唱をリアルタイムに視認できるようにします。
  - ヘッダーおよびショートカットバーから即座に確認できる「接続状態バッジ」と「マルチプレイ診断モーダル」を導入し、通信が正常稼働しているかをプレイヤー自身が一目で検証できるようにします。
- **対象プレイヤー**:
  - 広大なファンタジー大陸を仲間と冒険したいプレイヤー、およびネットワーク状況や同期遅延を確実に把握したいプレイヤー。
- **提供価値**:
  - 「動いているのか分からない」という不安を払拭する完全な可視性。
  - 電波切断やプレビュー環境特有の切断時でもフリーズやエラー画面を出さず、冒険が継続できる高い耐障害性。

---

## 2. ユーザー体験 & ビジュアルデザイン

### 主要ユーザーフロー
1. **ログイン・初期同期**:
   - ゲーム起動時、WebSocket `/ws` へ接続。成功時にヘッダーのステータスバッジが `🟢 オンライン (12ms)` へ点灯。
   - 自身のキャラクター情報（名前、クラス、レベル、初期座標）がサーバーへ登録（`join`）され、他クライアントに「冒険者がログインしました」と通知。
2. **常時ステータス監視**:
   - ヘッダー左上に接続ステータスバッジを常時表示：
     - **オンライン**: 鮮やかなエメラルドグリーン点灯、Ping表示（例: `32ms`）、接続中プレイヤー数。
     - **再接続中**: アンバーの点滅、再試行カウントダウン。
     - **オフライン（ソロモード）**: スレートグレー、単独モード表記。
3. **詳細診断モーダル（通信テストパネル）**:
   - ヘッダーのステータスバッジ、またはショートカットバーの「通信診断」ボタンをクリックして展開。
   - **診断内容**:
     - リアルタイムPing往復レイテンシ（5秒ごとの自動計測 + 「今すぐPingテスト」ボタン）。
     - 自身のクライアントIDと接続サーバー種別（Node.js WebSocket Server）。
     - 現在同じワールドに存在する冒険者リスト（名前、クラス、座標、HP、最終同期時間）。
     - 同期パケット送受信カウンター（Tx/Rx）。
4. **切断・オフライン自動フォールバック**:
   - ネットワークが切断された場合、画面に邪魔なモーダルやエラー音は出さず、右上に静かなトースト「ネットワーク切断: ソロプレイモードに切り替えました」を表示。
   - NPCモンスターとの戦闘、クエスト受注、アイテム収集、空間転送門（ワープ）などは一切止まらず継続。
   - バックグラウンドで3秒ごとに再接続を自動試行し、回復した瞬間に自動で他プレイヤーと再同期。

### ビジュアル・デザイン設計（Anti-AI Slop & WCAG AA準拠）
- **カラートークン**:
  - 接続正常: `text-emerald-400 bg-emerald-950/60 border-emerald-500/40`
  - 再接続試行中: `text-amber-400 bg-amber-950/60 border-amber-500/40`
  - オフライン: `text-slate-400 bg-slate-900/60 border-slate-700/40`
- **タイポグラフィ**: 数値・レイテンシ・座標には `font-mono tabular-nums` を徹底適用し、文字揺れを防止。
- **余白・レイアウト**: 診断モーダルは半透明のダークフロストガラス調（`backdrop-blur-md`）、内側パディング24px、要素間ギャップ12pxの規則正しいグリッド配置。

## 3. 主要な設計決定 & トレードオフ

### 決定 1: WebSocket ハンドシェイクと自動参加（Join）フローの是正
- **選択アプローチ**:
  - `multiplayer.connect()` 完了時およびサーバーからの `init` 受信時に、クライアント側から現在のプレイヤーデータ（クラス、レベル、HP、座標）を即時自動送信（`join`）する。
  - クラス切替やレベルアップ、テレポート時にも同期イベントを発行。
- **選定理由**:
  - 現在のコードでは接続確立後に `join` が送信されておらず、サーバーの内部プレイヤー一覧に登録されない致命的な初期化不整合が存在していたため。

### 決定 2: 診断モーダルとワンクリック「同期診断テスト」の導入
- **選択アプローチ**:
  - ユーザーが「正常に動いているか」をその場で体感できるように、診断モーダル内にリアルタイムエコーテスト（Echo/Ping Test）ボタンを設置。ボタンを押すと1往復のミリ秒を即時算出し、グリーンチェックマークを表示。
- **選定理由**:
  - 他の人間プレイヤーが同一セッションにログインしていないタイミングでも、バックエンドサーバーとの通信が100%正常に開通していることをプレイヤーが即時に確証できる。

### 決定 3: エラー発生時の非阻害的（Non-blocking）フォールバック
- **選択アプローチ**:
  - WebSocketの切断やエラー（例: Vite HMR切断やモバイル回線瞬断）時に、ゲームループを一切止めず、ローカルの物理・レンダリング・NPC AI・インベントリをそのまま実行。
- **選定理由**:
  - MMORPG型Webアプリにおいて、接続不良で画面がフリーズしたりアラートで遮られる体験は最悪のUXとなるため。

### パケット定義 & 通信プロトコル
| パケット種別 | 送信元 | ペイロード概要 | 目的 |
|---|---|---|---|
| `init` | Server → Client | `{ yourId, players, serverTime }` | 接続初期化と現在プレイヤー一覧の伝達 |
| `join` | Client → Server | `{ name, classId, level, hp, maxHp, x, y, z, rotation }` | プレイヤーの実装登録と他クライアントへの参加同報 |
| `player_joined` | Server → Client | `{ player: RemotePlayer }` | 新規参加者の描画モデル生成と通知トースト |
| `move` | Client → Server | `{ x, y, z, rotation, isMoving, isDashing }` | 座標同期（50msスロットリング） |
| `player_moved` | Server → Client | `{ id, x, y, z, rotation, isMoving, isDashing }` | 他プレイヤー位置のスムーズ補間移動 |
| `ping` / `pong` | 双方向 | `{ type: 'ping', t: timestamp }` | レイテンシ常時算出（5秒周期） |
| `echo` / `echo_ack` | 双方向 | `{ type: 'echo', t: timestamp }` | 診断モーダルでの手動即時通信テスト |
| `player_left` | Server → Client | `{ id }` | 切断時のメッシュ消去と離脱通知 |

## 5. 実装ステップ計画

1. **ステップ 1: `server.ts` の通信ハンドラ強化**
   - `join` パケット処理の堅牢化（未登録時の自動修復登録）。
   - 手動同期テスト用の `echo` イベントハンドラ追加。
   - 切断（close/error）時のメモリリーク防止と確実な `player_left` ブロードキャスト。

2. **ステップ 2: `src/utils/multiplayer.ts` の接続・同期フロー完全化**
   - `connect()` 後の自動 `join` 実行（初期化コールバックの設置）。
   - 接続ステータス管理（`connected` / `connecting` / `offline`）の正確なイベント通知。
   - `sendEchoTest()` メソッドの追加による即時レイテンシ計測。

3. **ステップ 3: `src/components/HUD/Modals/MultiplayerModal.tsx` の新規作成**
   - 接続状態、現在のPing、クライアントID、接続先URL。
   - 同期テスト実行ボタン（押すとリアルタイムにパケット往復時間を表示）。
   - 現在ワールド内にいるプレイヤー一覧（名前、職業、座標、HPバー）。
   - ソロモード／マルチプレイの説明とトラブルシューティング案内。

4. **ステップ 4: `Header.tsx` および `App.tsx` の統合**
   - ヘッダーの接続バッジをクリック可能にし、押すと診断モーダルが開くよう改善。
   - オフライン時の状態バッジ（灰色・ソロモード）と再接続中の点滅表示。
   - クラス変更時・リスポーン時の `multiplayer` への最新ステータス更新。

5. **ステップ 5: ビルド・検証**
   - `compile_applet` によるTypeScriptコンパイルの整合性確認。
   - 複数タブ接続や通信診断ボタンによる動作検証。
